How it works

Make room for serious Nix builds

Standard GitHub Actions runners ship tens of gigabytes of unused browsers, language runtimes, and container images. Nothing but Nix removes that bloat while your job keeps moving.

01 Instant Btrfs /nix pool
Claims free runner disk space in 1 to 3 seconds and mounts a zstd:1 compressed Btrfs volume at /nix before the purge even starts.
02 Parallel purge with rmz
Deletes unused SDKs, Docker images, snaps, and caches in the background with rmz, expanding the Btrfs pool dynamically as space frees up.
03 Four Hatchet Protocols
Pick holster, carve, cleave (default), or rampage to balance reclaimed disk space against preinstalled runner tools.
04 Ubuntu and Apple silicon runners
Tested on Ubuntu 22.04, 24.04, and 26.04 (x64 and arm64) plus Apple silicon macOS runners, while skipping Intel macOS, Windows, and container runners cleanly.

Hatchet Protocols

Choose how hard to swing

Every protocol hands control back to your workflow in about 2 seconds when running in the default background mode.

  1. holster

    Keep every tool

    ~76 GiB Linux · ~96 GiB macOS

    Removes nothing and breaks nothing. Pools existing free disk space for /nix.

  2. carve

    Fast reclaim

    ~105 GiB Linux · ~123 GiB macOS

    Drops unowned toolchains and caches while keeping Docker, apt packages, and Xcode.

  3. cleave

    Balanced default

    ~120 GiB Linux · ~269 GiB macOS

    Removes Docker, snaps, /usr/local, simulator runtimes, and extra Xcode installs.

  4. rampage

    Maximum Nix space

    ~129 GiB Linux · ~282 GiB macOS

    Clears remaining runtimes, browsers, databases, and Homebrew while keeping core Git tools.

Measured on public x64 Linux and macos-26 runners. On Linux, zstd:1 Btrfs compression lets /nix store more than raw disk sizes.

Get started

Drop into any Nix workflow

Place wimpysworld/nothing-but-nix@main immediately before your Nix installer step. Works with DeterminateSystems, Cachix, and nixbuild actions.

View on GitHub Marketplace Full configuration reference
Standard workflow (Cleave) 
- uses: wimpysworld/nothing-but-nix@main
- uses: DeterminateSystems/nix-installer-action@main
  with:
    extra-conf: |
      build-dir = /nix/build

Directs Nix derivation builds to /nix/build on the compressed Btrfs pool.

Maximum space before heavy builds 
- uses: wimpysworld/nothing-but-nix@main
  with:
    hatchet-protocol: 'rampage'
    witness-carnage: true

Runs the purge synchronously so all reclaimed space is ready before VM tests or large compilations start.

Custom safe havens and compression 
- uses: wimpysworld/nothing-but-nix@main
  with:
    hatchet-protocol: 'cleave'
    root-safe-haven: '16384'
    btrfs-compression: 'zstd:3'
    nix-permission-edict: true

Reserve extra space on / for Docker or large checkouts, tune Btrfs compression, or grant user ownership of /nix.

Questions

Frequently asked questions

Which GitHub Actions runners are supported?

Official Ubuntu runners (22.04, 24.04, and 26.04 on x64 and arm64) and Apple silicon macOS runners (macos-15 and macos-26). Intel macOS, Windows, and unprivileged container runners such as ubuntu-slim skip cleanly without failing the job.

Why did a large build still run out of space?

In default background mode, a build can outpace the purge. Set witness-carnage: true to wait for the full purge before your build begins, and set build-dir = /nix/build in your Nix configuration.

Do I need special permissions for Cachix or nixbuild?

Installers that write to /nix without sudo need nix-permission-edict: true, which sets ownership of /nix to the runner user after mounting.
